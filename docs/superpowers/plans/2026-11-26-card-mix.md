# Card Mix (both apps) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The two practice directions stop sharing their new cards: new cards are random from the 60 most common unseen, an item answered in the other direction within 7 days is held back, and a review answered in the other direction today goes last.

**Architecture:** All rules live in the shared pure module `js/srs.js` (byte-identical in both repos). Each answer records its day as `seen`. `app.js` passes a lookup for the other direction's card to the queue builder and to the counts.

**Tech Stack:** Plain ES modules, `node --test` (`"/c/Program Files/nodejs/node.exe"`, not on PATH).

**Spec:** `docs/superpowers/specs/2026-11-26-card-mix-design.md`

## Global Constraints

- `js/srs.js` and `tests/srs.test.js` are byte-identical in T (`c:\dev\hobby\turkish-app`) and S (`c:\dev\hobby\swedish-app`). Write them in T, then copy them to S.
- Values: `NEW_POOL = 60`, `HOLD_DAYS = 7`. An item is held back when the other direction's card has `seen` with `today - seen < HOLD_DAYS`.
- A card without `seen` (answered before this change, or migrated) is never held back.
- Commit messages must not contain reset, push or clean. Run one command per call, with no `cd`.

## Review Focus

1. **Switching direction right after doing today's new cards:** none of those words come up as new in the other direction (Task 2 app test).
2. **A topic with fewer than 15 eligible new words:** the queue offers what there is, and More doesn't promise cards that are held back (Task 2 test: canMore and the "M new" count use only eligible cards).
3. **Undo after a new card:** the card's previous state comes back without `seen`, so it isn't held back by mistake. This is covered by the existing undo test with `seen` added.
4. **Old cards and migrated marks without `seen`:** they're never held back (Task 1 test).
5. **App tests that depend on order:** practice tests fix `Math.random` so the queue is deterministic (Task 2).

### Task 1: The engine

**Files:** T `js/srs.js` and `tests/srs.test.js`, copied to S.

**Interfaces:**
- `answer(card, grade, today, rand)` now also sets `seen: today`. `stripped()` (for `prev`) does not include `seen`.
- `export const NEW_POOL = 60`, `export const HOLD_DAYS = 7`.
- `export function newCandidates(keys, cardOf, today, otherOf = () => undefined) → string[]`: the keys that are new in this direction and not held back, in the given order.
- `buildQueue(keys, cardOf, today, newLeft, rand, otherOf = () => undefined)`:
  - Due cards come first, oldest first and shuffled within a day, as now.
  - Due cards whose other card has `seen === today` are moved after the other due cards, keeping their order.
  - New cards are `shuffle(newCandidates(...).slice(0, NEW_POOL), rand).slice(0, max(0, newLeft))`.
